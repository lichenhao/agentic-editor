## 1. 项目概述与设计目标

### 1.1 项目定位
构建一个 **自进化、可考核的智能体集群运行框架**（Agent Harness），实现“1个人 + 一群Agent”高效协作模式。人类通过 **聊天式交互** 输入复杂需求，系统自动拆解、分配、执行、质检，并在运行中持续优化Agent质量，最终交付高质量成果。

### 1.2 核心设计目标
- **规范与执行分离**：人类以声明式配置定义操作权限、审批流程、安全边界，Agent运行时自动遵守。
- **Agent人格化（SOUL.md）**：为每个Agent定义独立的核心价值观、沟通风格、思维模式，形成稳定人格。
- **用户画像（USER.md）**：存储用户的背景、偏好、授权范围，用于个性化决策。
- **行为准则（AGENTS.md）**：定义Agent的工作流程、工具使用规范、异常处理策略。
- **长期记忆（MEMORY.md）**：存储Agent的经验教训和用户偏好积累。
- **上下文智能管理**：自动剪枝、压缩、优化对话历史，控制成本与性能。
- **分支与共享上下文**：支持实验性探索、多方案并行，同时复用全局知识。
- **对话式动态创建专业Agent**：用户通过自然语言即时生成新的Agent类型（Spec-Skills），并动态注册到系统。
- **考核测评机制**：为每个Agent建立token消耗和产出质量考核，劣质Agent自动重制，优秀Agent留存为模板。
- **任务状态全程可观测**：提供实时进度跟踪、工具调用详情、审批状态等。
- **人机协同交互**：以 **聊天 + 功能卡片** 为主界面，管理员后台提供传统GUI用于系统管理。

## 3. Agent 灵魂配置体系（基于 OpenClaw 标准）

### 3.1 文件体系与职责

| 文件 | 作用 | 回答的问题 |
|------|------|-----------|
| **SOUL.md** | Agent 的灵魂与价值观 | 它是谁？它相信什么？它如何沟通？它如何思考？ |
| **USER.md** | 用户的画像与偏好 | 它为谁服务？用户喜欢什么？用户授权什么？ |
| **AGENTS.md** | 行为准则与工作流程 | 它具体怎么干活？工具怎么用？出错怎么办？ |
| **MEMORY.md** | 长期记忆与经验 | 它记住了什么？学到了什么？ |
| **HEARTBEAT.md** | 定时任务与主动行为 | 它什么时候主动做事？（可选） |

### 3.3 配置文件加载与注入
- 在 Agent 初始化时，从数据库加载对应的 SOUL.md、USER.md、AGENTS.md、MEMORY.md。
- 将内容转换为 **系统消息（SystemMessage）** 注入到 LangGraph 的初始状态中。
- 示例：
  ```typescript
  const systemPrompt = `
  ${soulContent}
  
  --- 用户信息 ---
  ${userContent}
  
  --- 行为准则 ---
  ${agentsContent}
  
  --- 历史记忆 ---
  ${memoryContent}
  `;
  ```

- 允许在运行时通过对话动态更新部分配置（如用户授权范围）。

## 5. 核心模块详细设计（调整部分）

### 5.1 上下文管理器（增加配置注入）
- **功能**：在每次 Agent 运行前，将 SOUL/USER/AGENTS/MEMORY 等配置合并为系统消息，作为对话的固定前缀。
- **实现**：在 LangGraph 的 `beforeModel` 中间件中动态构建系统消息。
- **支持热更新**：配置文件变更后，新启动的 Agent 线程加载新配置，运行中的线程保持旧配置（避免中断）。

### 5.2 用户个性化决策（迁移至 USER.md）
- 原方案中“SOUL.md”中的超时自动决策功能，现移至 **USER.md 的“授权范围”** 部分。
- 决策引擎读取 USER.md，在审批超时后根据授权规则自动批准/拒绝。
- 授权规则支持通配符、正则等模式匹配。

### 5.3 策略网关（与 AGENTS.md 协同）
- 工具调用的审批策略来源：
  1. **全局策略**（Policy Store，管理员定义）
  2. **AGENTS.md 中的工具使用规范**（可覆盖全局策略，允许更细粒度的 Agent 定制）
- 决策顺序：AGENTS.md 规范 > 全局策略 > 默认规则。

### 5.4 动态 Agent 创建（继承配置）
- 当用户通过对话创建新 Skill（专业 Agent）时，系统会生成该 Skill 的 **SOUL.md** 和 **AGENTS.md** 基础模板。
- 用户可后续编辑这些文件，定制新 Agent 的行为。
- 新 Agent 的 **USER.md** 默认继承当前用户的 USER.md，但可独立覆盖（如为不同项目设置不同授权）。

## 6. 数据模型补充

在 PostgreSQL 中增加配置表：

```sql
-- Agent 配置表（每个 Agent 模板或实例可拥有独立配置）
CREATE TABLE agent_configs (
    id UUID PRIMARY KEY,
    agent_id UUID REFERENCES agents(id),
    config_type VARCHAR(20) NOT NULL, -- 'soul', 'user', 'agents', 'memory'
    content TEXT NOT NULL,
    version INTEGER NOT NULL DEFAULT 1,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- 用户级默认配置（当 Agent 没有专属配置时使用）
CREATE TABLE user_default_configs (
    user_id UUID PRIMARY KEY REFERENCES users(id),
    soul_content TEXT,
    user_content TEXT,
    agents_content TEXT,
    memory_content TEXT
);
```
