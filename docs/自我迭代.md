# Agent 自我迭代与自我纠错机制设计

## 1. 概述

为实现 Agent 集群的持续进化，系统内置 **自我迭代更新** 与 **自我纠错** 机制。通过 **测评 Agent** 对产出的自动评估、以及 **考核指标** 的实时监控，Agent 能够识别自身不足，触发优化流程，最终形成“执行 → 评估 → 学习 → 改进”的闭环。

---

## 2. 核心概念与组件

| 组件 | 职责 |
|------|------|
| **考核指标采集器** | 收集每次任务的 token 消耗、耗时、用户反馈、修改次数等数据。 |
| **评估引擎** | 基于规则或机器学习模型，判断 Agent 是否需要优化（重制、参数调整）。 |
| **测评 Agent** | 一个特殊的 Agent，用于自动评估其他 Agent 的产出质量，并提供改进建议。 |
| **经验知识库** | 存储失败案例、优秀配置模板，供 Agent 学习。 |
| **配置优化器** | 根据评估结果，调整 Agent 的 SOUL.md、AGENTS.md 等配置文件。 |
| **生命周期管理器** | 执行 Agent 的重制、销毁、创建操作。 |

---

## 3. 自我迭代更新机制

### 3.1 触发条件

Agent 的自我迭代由以下事件触发：

| 触发类型 | 条件 | 示例 |
|----------|------|------|
| **考核指标阈值** | 连续驳回次数 ≥ N（可配置） | 某 Agent 连续 3 次产出被用户驳回 |
| **性能异常** | token 消耗超过同类任务平均值的 2 倍 | 某 Agent 单次任务消耗 5 万 tokens，而同类平均 1 万 |
| **用户主动请求** | 用户通过 UI 点击“优化此 Agent” | 用户对 Agent 表现不满意 |
| **测评 Agent 主动推荐** | 测评 Agent 发现可优化的模式 | 测评 Agent 分析日志后建议调整提示词 |

### 3.2 迭代方式

#### 3.2.1 轻度优化（参数微调）
- **适用场景**：轻微性能下降、产出偶尔偏差。
- **操作**：
  - 调整 AGENTS.md 中的工具使用规范（如增加重试次数）。
  - 微调 SOUL.md 的沟通风格或思维模式。
  - 更新 MEMORY.md 中的经验教训（如添加失败案例）。
- **实现**：配置优化器根据评估结果生成新的配置文件版本，Agent 下次任务加载新配置。

#### 3.2.2 中度优化（提示词工程）
- **适用场景**：产出质量持续不佳、用户反馈反复。
- **操作**：
  - 使用测评 Agent 或 LLM 重新生成 SOUL.md 的核心原则部分。
  - 优化系统提示词中的任务分解策略。
- **实现**：调用 LLM 分析失败案例，生成改进后的提示词模板，人工或自动应用。

#### 3.2.3 重度优化（重制 Agent）
- **适用场景**：连续多次不合格、工具调用频繁失败。
- **操作**：
  1. **归档失败经验**：将 Agent 的配置、失败任务日志存入经验知识库。
  2. **销毁原 Agent**：清除 Redis 中的状态，释放资源。
  3. **生成新 Agent**：基于原模板 + 失败经验，生成新的 SOUL.md 和 AGENTS.md（可能调整工具集）。
  4. **重新注册**：新 Agent 使用原 ID 或新 ID，但继承历史考核数据的部分属性（如优秀模板标记）。
- **实现**：生命周期管理器执行上述流程，并记录重制日志。

### 3.3 经验学习与传承

- **经验知识库**：存储失败案例（包括任务描述、失败原因、修改建议）和优秀配置模板。
- **传承方式**：
  - 当创建新 Agent 时，从知识库中检索与任务类型相似的失败案例，将其作为系统消息的一部分，提醒新 Agent 避免重蹈覆辙。
  - 优秀配置模板被标记为 `is_excellent`，后续创建同类 Agent 时可作为基座。

## 4. 自我纠错机制（基于测评 Agent）

### 4.1 测评 Agent 的角色与能力

测评 Agent 是一个具有 **评估权限** 的特殊 Agent，它的核心职责是：

- **产出质量评估**：对子 Agent 的产出进行自动化检查（如代码语法、报告完整性、逻辑一致性）。
- **改进建议生成**：为不合格的产出提供具体的修改建议。
- **模式识别**：分析历史数据，识别 Agent 的常见错误模式，主动触发迭代。

#### 4.1.1 测评 Agent 的配置
- 拥有更高的模型调用预算（因为评估任务通常不需要大模型）。
- 工具集：可访问考核数据库、审计日志、经验知识库。
- 系统提示词强调“客观、建设性、可操作”。

### 4.2 自我纠错流程

#### 4.2.1 执行时纠错（实时）
当 Agent 在任务执行中遇到工具调用失败或逻辑异常时，系统可以立即引入测评 Agent 介入：

1. **捕获错误**：工具执行失败时，LangGraph 节点抛出异常。
2. **调用测评 Agent**：将错误信息、当前状态、历史消息传递给测评 Agent。
3. **生成修正方案**：测评 Agent 分析错误，可能给出：
   - 重试建议（如调整参数后重试）
   - 替代方案（换用其他工具）
   - 中断请求（需人工介入）
4. **恢复执行**：Agent 根据建议执行修正操作，或进入 HITL 等待。

#### 4.2.2 任务后纠错（离线）
当用户反馈不合格（驳回）或考核指标显示质量问题时，触发事后纠错：

1. **记录失败**：将任务详情存入考核数据仓库。
2. **异步调用测评 Agent**：对失败任务进行深度分析，输出：
   - 根本原因（提示词问题、工具选择不当、上下文缺失等）
   - 具体改进建议（修改哪个部分的配置）
3. **应用改进**：
   - 如果是轻度问题，自动应用建议（如更新 AGENTS.md）。
   - 如果是严重问题，将分析报告发送给管理员或触发重制。

#### 4.2.3 主动纠错（预判）
测评 Agent 定期扫描考核数据，识别具有潜在风险的 Agent（如评分呈下降趋势）：

- 主动生成优化建议，并推送给管理员或用户。
- 若用户授权自动优化，则直接执行轻度优化。

### 4.3 测评 Agent 的设计要点

#### 4.3.1 安全性
- 测评 Agent 只能读取数据，不能执行工具（除分析工具外），避免二次破坏。
- 其建议必须经过策略网关审批（可配置为自动应用或人工确认）。

#### 4.3.2 评估标准
- 可根据任务类型动态加载评估规则（如代码类任务检查 lint，报告类检查结构）。
- 支持自定义评估指标（用户可在 AGENTS.md 中定义期望的输出格式）。

#### 4.3.3 可观测性
- 所有测评 Agent 的评估过程和结果均被记录审计，便于追溯。

```typescript
class ConfigOptimizer {
  async optimize(agentId: string, feedback: string) {
    const currentConfig = await getAgentConfig(agentId);
    const improved = await this.callLLM(`
      当前 Agent 配置：
      ${JSON.stringify(currentConfig)}
      
      用户反馈/失败原因：
      ${feedback}
      
      请优化 AGENTS.md 中的工具使用规范或 SOUL.md 中的思维模式。
    `);
    await saveAgentConfig(agentId, improved);
    return improved;
  }
}
```

const agentGraph = new StateGraph(AgentState)
  .addNode("agent", callLLM)
  .addNode("tools", executeTools)

    if (state.toolError) {
      const correction = await evaluatorAgent.invoke({
        error: state.toolError,
        context: state.messages,
      });
      return { correctionPlan: correction };
    }
  })
  .addConditionalEdges("evaluate", (state) => {
    if (state.correctionPlan) return "agent"; // 重试
    return "human_approval";

## 6. 与现有功能的融合

| 现有功能 | 融合方式 |
|----------|----------|
| **考核测评机制** | 测评 Agent 的输出直接作为考核数据的一部分，影响评分。 |
| **Agent 生命周期管理** | 重制时调用配置优化器，基于失败经验生成新配置。 |
| **上下文管理** | 测评 Agent 的建议可被注入到 Agent 的系统消息中，作为“即时学习”。 |
| **分支上下文** | 可创建分支用于 A/B 测试不同的优化策略，对比考核指标。 |
| **SOUL/USER/AGENTS 配置** | 优化器直接修改这些配置文件，实现迭代。 |

---

## 7. 总结

通过引入 **测评 Agent** 和 **自我迭代更新** 机制，Agent Harness 实现了：

- **闭环进化**：Agent 能够根据考核结果自动调整自身行为，减少人工干预。
- **即时纠错**：执行中的错误可被捕获并尝试自动修正，提升任务成功率。
- **知识传承**：失败经验和优秀模板被积累，惠及后续 Agent 的创建。

这套设计使 Agent 集群从静态执行者进化为能够持续学习、自我优化的智能体，真正实现“1个人 + 一群Agent”高效解决高复杂度问题的愿景。
