# 总体架构设计

## 1. 概述

本文档定义 Agent Harness 的总体架构，包括技术选型、分层设计、核心组件交互。

## 2. 技术选型

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| **Agent 编排** | Claude API + LangGraph | 使用 LangGraph 实现 Supervisor 和子 Agent 的状态机 |
| **API 框架** | Hono | 轻量级高性能 REST 框架，支持 SSE |
| **主数据库** | PostgreSQL | 结构化数据存储（用户、Agent、任务、策略） |
| **缓存** | Redis | 线程状态、任务进度、用户画像缓存 |
| **时序数据库** | ClickHouse | Agent 指标、工具调用时序数据 |
| **可观测性** | OpenTelemetry | 分布式追踪、指标采集 |

## 4. 核心组件交互

### 4.1 任务执行流程

```
用户输入 → API → Supervisor Agent → 需求拆解 → 创建子 Agent → 执行 → 聚合结果 → 考核评估
```

### 4.2 审批流程

```
Agent 请求操作 → Policy Engine 检查 → 需要审批?
  ├── 否 → 执行操作
  └── 是 → USER.md 自动决策
              ├── 可自动执行 → 执行
              └── 需用户确认 → SSE 推送审批请求 → 用户决策 → 继续/终止
```

### 4.3 自我迭代流程

```
任务完成 → 考核评估 → 触发迭代条件?
  ├── 否 → 归档
  └── 是 → 自我迭代管理器
              ├── 轻度 → 更新 AGENTS.md/MEMORY.md
              ├── 中度 → 更新 SOUL.md
              └── 重度 → 重制 Agent
```

## 5. 配置文件体系

参考 [docs/files.yaml](../files.yaml)：

| 文件 | 用途 | 可被迭代修改 |
|------|------|-------------|
| **SOUL.md** | Agent 灵魂：核心身份、原则、沟通风格、思维模式 | 中度/重度迭代 |
| **USER.md** | 用户画像：基本信息、偏好设置、授权范围 | 系统管理 |
| **AGENTS.md** | 行为准则：工作流程、工具规范、异常处理 | 轻度迭代 |
| **MEMORY.md** | 长期记忆：决策记录、经验教训 | 轻度迭代 |

## 6. 多租户设计

- 所有表增加 `tenant_id` 字段
- 策略和 USER.md 按租户隔离
- Redis key 添加租户前缀

## 7. 可扩展性设计

- **水平扩展**: Redis Cluster + 无状态 API + 任务队列
- **异构 Agent**: 支持远程微服务（MCP 协议）接入
- **多租户**: 租户间完全隔离
